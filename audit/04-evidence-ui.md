# 04 — Evidence ledger: UI / controls / accessibility (agent `ui`)

Method: built client served by `node server/dist/index.js` on port 8102 (`VW_DEV_NO_TIME_CHECK=1`), driven with Playwright 1.63 + Chromium on SwiftShader (software GL, DPR 1 unless stated). Screens opened via the `?screen=` jump points with `seed=1234&theme=desert&headless=1`. axe-core 4.10.2 installed in the agent scratch dir and injected with `page.addScriptTag`. All scripts and raw JSON/TXT outputs are under `/tmp/claude-0/-home-user-Sandbox/0037d5dc-0f14-5959-95a4-43546256ef08/scratchpad/agent-ui/` (`axe.mjs`→`axe.json`, `keyboard.mjs`→`keyboard.txt`, `pause.mjs`→`pause.txt`, `legibility.mjs`→`legibility.json`, `viewport.mjs`→`viewport.json`, `l10n.mjs`→`l10n.json`, `focus.mjs`; screenshots in `shots/`). Three leaderboard rows were seeded through the public API (`POST /api/session` + `POST /api/score`) so row interactions could be tested. Note: the server could not be stopped at the end (process kill was denied by the sandbox policy); it is still listening on 8102.

Contrast method: for each text element, the element was hidden (`visibility:hidden`), the pixels beneath its bounding box were sampled from a screenshot, and the WCAG 2.x ratio of the computed `color` was taken against the brightest, 95th-percentile and median pixel. For elements whose own `background` is the plate (buttons, `kbd`, tabs) hiding removes the fill, so those are computed analytically from the two CSS colours (noted inline). Text-shadows are ignored, as the WCAG formula requires.
